# Java数据结构学习笔记（第一篇）：初识集合框架

> Java 基础篇到这里告一段落，从这篇开始换一个新系列：数据结构。第一篇先不急着写代码实现，而是把整个地图铺开——集合框架是什么、为什么要有它、后面要学的容器各自底层是什么结构、数据结构和算法到底在解决什么问题。

---

## 一、从一个通讯录说起

手机里的通讯录，平时用起来很顺手：加个人、搜个名字、删掉一个不用的号码，点两下就完事。

但如果我们自己动手，用最基础的数组来实现一个通讯录，事情就没那么轻松了：

- 通讯录里现在有 3 个人，明天加到 100 个，数组开多大合适？
- 删掉中间某个人，后面的位置怎么补？
- 想按名字查号码，除了从头遍历还能怎么办？
- 一个名字要对应一个号码，数组只能存一列，怎么表达这种对应关系？

这些问题不是"代码写得不够熟练"，而是**数据怎么组织**的问题。Java 给出的答案是：用集合框架。

---

## 二、集合框架到底是什么

Java 集合框架（Java Collection Framework），又叫**容器**（container），是定义在 `java.util` 包下的一组接口和它们的实现类。

它的作用一句话就能说完：**把多个元素放在一个单元里，方便快速存储、检索和管理**——也就是平时说的增删查改（CRUD）。

生活里的例子到处都是：一副扑克牌是一组牌的集合，一个邮箱是一组邮件的集合，一个通讯录是一组"姓名 → 电话"的映射。

先看一眼用集合写通讯录是什么感觉：

```java
import java.util.ArrayList;

public class Ds1 {
    public static void main(String[] args) {
        ArrayList<String> contacts = new ArrayList<>();
        contacts.add("小明");
        contacts.add("小红");
        contacts.add("小刚");

        System.out.println("通讯录：" + contacts);
        System.out.println("一共有 " + contacts.size() + " 个人");

        contacts.remove("小红");
        System.out.println("删掉小红后：" + contacts);

        System.out.println("有没有小明：" + contacts.contains("小明"));
        System.out.println("小明排在第几个：" + contacts.indexOf("小明"));
    }
}
```

运行结果：

```
通讯录：[小明, 小红, 小刚]
一共有 3 个人
删掉小红后：[小明, 小刚]
有没有小明：true
小明排在第几个：0
```

没有声明长度，没有手动挪元素，删掉"小红"之后剩下的人自动往前补位。这几个方法的名字也很直白：

| 方法 | 作用 |
|------|------|
| `add(元素)` | 添加一个元素 |
| `remove(元素)` | 删除指定元素 |
| `size()` | 当前元素个数 |
| `contains(元素)` | 是否包含某个元素 |
| `indexOf(元素)` | 元素所在的下标，找不到返回 -1 |

> 💡 打印出来的 `[小明, 小红, 小刚]` 这种方括号格式，是因为 `ArrayList` 重写了 `toString` 方法，不需要自己再写循环拼字符串。

## 三、只用数组会有哪些麻烦

为了看清集合框架的价值，先看数组版本有多别扭。

假设通讯录存在一个长度为 5 的数组里，现在要删掉中间那个"小红"：

```java
import java.util.Arrays;

public class Ds2 {
    public static void main(String[] args) {
        String[] names = {"小明", "小红", "小刚", null, null};
        int size = 3;

        // 想删掉下标 1 的"小红"，只能自己把后面的元素一个个往前挪
        for (int i = 1; i < size - 1; i++) {
            names[i] = names[i + 1];
        }
        names[size - 1] = null;
        size--;

        System.out.println(Arrays.toString(names));
        System.out.println("现在还剩 " + size + " 个人");
    }
}
```

运行结果：

```
[小明, 小刚, null, null, null]
现在还剩 2 个人
```

注意两个细节：删除之后必须把最后一个位置置为 `null`，否则"小刚"会在数组里出现两次；而且还要自己维护一个 `size` 变量，因为 `names.length` 永远是 5，不代表真有几个人。

数组的四道坎，可以列成这样：

| 问题 | 具体表现 | 集合框架怎么解决 |
|------|---------|----------------|
| 长度固定 | 一开始就得定死，满了没法再加 | 内部自动扩容 |
| 删除要挪元素 | 删中间一个，后面全部前移，还要处理尾巴 | `remove` 一步搞定 |
| 查找只能遍历 | 找某个名字得写循环 | `contains` / `indexOf` |
| 表达不了映射 | 一列只能存一个值，存不下"姓名 → 电话" | 用 `Map` 存键值对 |

第四点单独看一眼。同样是通讯录，如果要存"名字对应号码"，数组就无能为力了，得换成 `Map`：

```java
import java.util.HashMap;
import java.util.Map;

public class Ds4 {
    public static void main(String[] args) {
        Map<String, String> phoneBook = new HashMap<>();
        phoneBook.put("小明", "13800000001");
        phoneBook.put("小红", "13800000002");

        System.out.println("小明的电话：" + phoneBook.get("小明"));
        System.out.println("通讯录里有几个人：" + phoneBook.size());
        System.out.println("有没有小刚：" + phoneBook.containsKey("小刚"));
    }
}
```

运行结果：

```
小明的电话：13800000001
通讯录里有几个人：2
有没有小刚：false
```

`put` 存一对"键和值"，`get` 按键取值，不用管它存在第几个位置。这就是集合框架里另一条完全不同的思路。

> 💡 到这里其实已经能看出集合框架分两大类：一类像 `ArrayList`，存的是一串单个元素；一类像 `HashMap`，存的是一组"键 → 值"的对应关系。

## 四、集合框架的整体结构

搞清楚有哪两大类之后，整体结构就好记了：

```
Collection（接口）：一次存一个元素
├── List（接口）        有序、可重复、有下标
│   ├── ArrayList       底层是数组
│   ├── LinkedList      底层是双向链表
│   └── Vector          老版本，现在基本不用
├── Set（接口）         不重复
│   ├── HashSet         底层是哈希表，不保证顺序
│   └── TreeSet         底层是红黑树，按大小排序
├── Queue（接口）       队列，先进先出
│   └── PriorityQueue   底层是堆，按优先级出队
├── Deque（接口）       双端队列
│   └── LinkedList      同一个类，也能当队列用
└── Stack               栈，后进先出

Map（接口）：存"键 → 值"，独立于 Collection
├── HashMap             底层是哈希表
├── TreeMap             底层是红黑树，按键排序
└── Hashtable           老版本，现在基本不用
```

两个分支的区别，用一张表说清楚：

| | Collection | Map |
|---|---|---|
| 存什么 | 一个个单独的元素 | 一对对的键值（key → value） |
| 能不能按下标取 | `List` 可以 | 不能，只能按 key 取 |
| 元素能不能重复 | `List` 可以，`Set` 不行 | key 不能重复，value 可以 |
| 典型代表 | `ArrayList`、`HashSet` | `HashMap`、`TreeMap` |
| 生活比喻 | 一排储物格，每格放一件东西 | 存包处的号码牌，凭牌取包 |

> **⚠️ 注意：** `Map` **不是** `Collection` 的子接口，它是独立的一条分支。这点初学时特别容易记混——判断依据很简单：`Map` 里存的是"一对"，`Collection` 里存的是"一个"。

再补一个容易困惑的点：`List` 说的"有序"，指的是**按添加顺序排列、每个元素有确定下标**，不是"自动帮你排好大小"。想按分数排序，得自己调 `sort`。

## 五、后面会遇到的容器，底层都是什么

集合框架里每个容器，本质上都是对某一种数据结构的封装。先混个脸熟，后面每个都会单独讲、单独手写实现：

| 容器 | 属于 | 底层数据结构 | 特点 |
|------|------|-------------|------|
| `ArrayList` | List | 动态数组（顺序表） | 按下标访问快，中间插入删除慢 |
| `LinkedList` | List / Deque | 双向链表 | 头尾增删快，按下标访问慢 |
| `Stack` | —— | 栈（特殊的顺序表） | 后进先出 |
| `Queue` | Queue | 队列（特殊的顺序表） | 先进先出 |
| `Deque` | Deque | 双端队列 | 两头都能进出 |
| `PriorityQueue` | Queue | 堆 | 每次出队的是优先级最高的 |
| `HashSet` | Set | 哈希表 | 查询接近 O(1)，不保证顺序 |
| `TreeSet` | Set | 红黑树 | 查询 O(log n)，按大小有序 |
| `HashMap` | Map | 哈希表 | 按键查询接近 O(1) |
| `TreeMap` | Map | 红黑树 | 按键查询 O(log n)，按键有序 |

`O(1)`、`O(log n)` 这种写法叫时间复杂度，第二篇会专门讲，这里先记住"哈希表快、红黑树有序"这个印象就行。

> 💡 为什么一开始就要知道底层？因为**同样是存 10 万条数据，选错容器可能慢几十倍**。比如频繁在列表头部插入，用 `ArrayList` 每次都要整体后移，用 `LinkedList` 只要改两个指针。

除了这些容器，后面还会单独讲两种基础结构：

- **二叉树**：每个节点最多两个分支，是 `TreeSet`、`TreeMap` 的地基
- **堆**：一种特殊的完全二叉树，是 `PriorityQueue` 的地基

## 六、数据结构到底是什么

课件里的定义是：数据结构是计算机**存储、组织数据的方式**，指相互之间存在一种或多种特定关系的数据元素的集合。

这句话有点绕，翻译一下：**数据不是随便堆着的，它们之间有关系，而怎么安排这些关系，就是数据结构。**

按元素之间的关系，常见的有四类：

| 关系 | 名称 | 例子 |
|------|------|------|
| 一对一 | 线性结构 | 排队买奶茶，每个人前面只有一个、后面也只有一个 |
| 一对多 | 树形结构 | 公司的组织架构，一个主管带几个组员 |
| 多对多 | 图形结构 | 地铁线路图，一个站可以和好几个站相连 |
| 无关系 | 集合 | 抽屉里的一堆杂物，彼此之间没有顺序 |

> 💡 用厨房收纳来类比就很好懂：锅碗瓢盆都是那些东西，但用抽屉、挂墙架还是旋转托盘，取用起来的效率完全不同。数据结构解决的就是"**怎么摆**"的问题。

## 七、算法是什么

课件里的定义：算法是**定义良好的计算过程**，它取一个或一组值作为输入，产生一个或一组值作为输出。简单说，算法就是一系列计算步骤，把输入数据变成输出结果。

如果数据结构是"怎么摆"，那算法就是"**怎么动**"——按什么步骤去操作这些数据。

拿"找出一组分数里的最高分"举例：

```java
public class Ds3 {
    public static void main(String[] args) {
        int[] scores = {88, 92, 79, 95, 86};

        int max = scores[0];
        for (int i = 1; i < scores.length; i++) {
            if (scores[i] > max) {
                max = scores[i];
            }
        }

        System.out.println("最高分：" + max);
    }
}
```

运行结果：

```
最高分：95
```

这段代码里的"算法"就三步：

1. 先把第一个分数当成当前最高分
2. 从第二个开始逐个比较，遇到更大的就更新
3. 全部比完，留下的就是最高分

> 💡 算法像菜谱：食材是输入，做出来的菜是输出，中间的火候、顺序、翻炒次数就是步骤。步骤写得对不对，直接决定这盘菜能不能吃。

同一个问题可以有很多种算法。比如找最高分，也可以先排序再取最后一个，结果一样，但花的力气不同——衡量"花多少力气"的指标，就是下一篇要讲的时间复杂度和空间复杂度。

## 八、为什么值得花时间学

**第一，开发时真的省事。**

成熟的集合框架已经把扩容、删除、查找这些琐事封装好了，不用每次都手写一遍。写业务代码时，直接 `add`、`get`、`remove` 就行，稳定性和边界情况都有保证。

**第二，能选对容器。**

知道 `ArrayList` 按下标快、`LinkedList` 头尾增删快，才不会在一个天天往头部插入的场景里用错容器。这种"知道什么时候该用哪个"，靠背 API 是背不出来的，得理解底层结构。

**第三，面试基本躲不开。**

Java 后端方向的面试里，数据结构相关的提问频率非常高，常见的有这么几类：

- `ArrayList` 和 `LinkedList` 的区别，各自适合什么场景
- `HashMap` 的底层实现，扩容是怎么做的
- `hashCode` 和 `equals` 有什么关系，作为 key 时要注意什么
- `HashSet` 和 `HashMap` 有什么区别
- 手写题：判断一个链表是不是回文、用两个栈实现队列

这些问题没有一个是靠背结论能答好的，都得真正理解结构和过程。

**第四，后面读源码会轻松很多。**

JDK 里 `ArrayList` 的扩容、`HashMap` 的树化，这些源码之所以看着费劲，就是因为不知道它在模拟什么结构。先把结构想明白，源码就只是"用代码把这个结构实现了一遍"。

## 九、这套笔记打算怎么学

课件里给了几条建议，我按自己的理解整理一下：

**先画图，再看代码。**

链表、二叉树、堆这些东西，光看代码很难在脑子里建立起形象。先画一张图——节点在哪、指针指哪、插入之后变成什么样——再回头读代码，会顺畅很多。后面每讲一个结构，我都会先给示意图。

**能手写就手写，别只调 API。**

`ArrayList` 用起来就那几个方法，但真正理解"动态扩容"这件事，必须自己写一遍带扩容的版本。这个系列会尽量给出手写实现，而不是只讲怎么用。

**刷题保持手感。**

LeetCode 和牛客都可以，从简单题开始，重点是把学过的结构用起来，而不是追求题量。

**写完要总结。**

每篇末尾留一段总结，把这一篇的主线收一下，过一段时间回头翻，比重新看一遍正文快得多。

## 总结

这一篇是整套笔记的地图，几个关键点：

**集合框架是什么：**
- `java.util` 包下的一组接口和实现类，俗称容器
- 作用是把多个元素放在一个单元里，方便增删查改

**集合框架的两大分支：**
- `Collection`：一次存一个元素，下面分 `List`、`Set`、`Queue`、`Deque`、`Stack`
- `Map`：存"键 → 值"，独立于 `Collection`，不属于它

**四个核心接口的性格：**
- `List`：有序、可重复、有下标
- `Set`：不重复，`HashSet` 不保证顺序、`TreeSet` 按大小排序
- `Queue` / `Deque`：排队进出，`Deque` 两头都能进出
- `Map`：按键取值，key 不能重复

**底层结构决定性能：**
- 数组 → 随机访问快，中间增删慢（`ArrayList`）
- 链表 → 增删快，随机访问慢（`LinkedList`）
- 哈希表 → 查询接近 O(1)，无序（`HashSet`、`HashMap`）
- 红黑树 → 查询 O(log n)，有序（`TreeSet`、`TreeMap`）
- 堆 → 每次取出最值（`PriorityQueue`）

**数据结构和算法的关系：**
- 数据结构管"怎么摆"，算法管"怎么动"
- 同一件事有很多算法，衡量好坏要看时间复杂度和空间复杂度

下一篇就开始讲这两个复杂度——怎么数一个算法的"步数"，`O(1)`、`O(n)`、`O(n²)` 到底是怎么算出来的，为什么二分查找能比逐个遍历快那么多。这块内容是后面所有结构性能分析的基础，值得慢慢磨。
